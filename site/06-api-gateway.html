Layer 06 · Core

Building the API gateway

The public surface. Two ideas carry it: dependency injection, so authentication is declared rather than repeated, and Server-Sent Events, so a ten-second generation feels like a hundred-millisecond one.

The problem it solves

Every protected route needs the same six steps: read the header, sanitise it, verify the signature, check expiry, load the subject, bind it to the logging context. Written inline, that is six chances per route to get it wrong — and the route someone forgets is the one that gets found.

Second problem: LLMs are slow. A blocking /chat that returns after eight seconds is indistinguishable from a broken one. Streaming does not make generation faster; it makes the wait legible.

Two token types, deliberately

A user token has sub = user.id and can open sessions. A session token has sub = session.id and can only talk to that one thread. A leaked session token exposes one conversation; a leaked user token exposes the account. Both are minted by the same create_access_token — the scoping is entirely in what you put in sub, which means the two dependency functions below are what actually enforce the boundary.

Dependency injection as an auth gate

FastAPI resolves declared dependencies before the handler body runs. Raise inside a dependency and the handler never executes — which is what makes this a gate and not a convention. 

router = APIRouter()
security = HTTPBearer()          # expects: Authorization: Bearer <token>


async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
) -> User:
    try:
        # Headers are user input like any other
        token = sanitize_string(credentials.credentials)

        user_id = verify_token(token)                 # signature + expiry
        if user_id is None:
            logger.warning("invalid_token_attempt")
            raise HTTPException(status_code=401,
                                detail="Invalid authentication credentials",
                                headers={"WWW-Authenticate": "Bearer"})

        # Signature valid ≠ user still exists. Deleted accounts hold
        # valid tokens for the rest of the 30-day window.
        user = await database_service.get_user(int(user_id))
        if user is None:
            logger.warning("user_not_found_from_token", user_id=user_id)
            raise HTTPException(status_code=404, detail="User not found",
                                headers={"WWW-Authenticate": "Bearer"})

        # Every log line from here on carries user_id automatically
        bind_context(user_id=int(user_id))
        return user

    except ValueError as ve:
        logger.error("token_validation_error", error=str(ve))
        raise HTTPException(status_code=422, detail="Invalid token format",
                            headers={"WWW-Authenticate": "Bearer"})

async def get_current_session(
    credentials: HTTPAuthorizationCredentials = Depends(security),
) -> Session:
    """Same shape, but the subject is a session id."""
    try:
        token = sanitize_string(credentials.credentials)
        session_id = verify_token(token)
        if session_id is None:
            raise HTTPException(status_code=401, detail="Invalid token")

        session = await database_service.get_session(sanitize_string(session_id))
        if session is None:
            raise HTTPException(status_code=404, detail="Session not found")

        bind_context(user_id=session.user_id, session_id=session.id)
        return session
    except ValueError:
        raise HTTPException(status_code=422, detail="Invalid token format")

Using it costs one line, and the type annotation is the documentation:

@router.post("/chat", response_model=ChatResponse)
@limiter.limit(settings.RATE_LIMIT_ENDPOINTS["chat"][0])
async def chat(
    request: Request,
    chat_request: ChatRequest,
    session: Session = Depends(get_current_session),   # ← the whole auth story
):
    result = await agent.get_response(
        chat_request.messages,
        session_id=session.id,               # thread_id for graph persistence
        user_id=str(session.user_id),        # tenancy key for long-term memory
    )
    return ChatResponse(messages=result)
Authentication, not authorisation

get_current_session proves the caller holds a valid token for a session and loads it. Because the session id comes from inside the signed token rather than from the URL, a caller cannot point at someone else's thread — the signature is the ownership proof. That works for the chat routes. For any route that takes an id in the path, though, you need an explicit session.user_id == current_user.id check; the dependency alone will not save you there.

Registration and login

@router.post("/register", response_model=UserResponse)
@limiter.limit(settings.RATE_LIMIT_ENDPOINTS["register"][0])
async def register_user(request: Request, user_data: UserCreate):
    try:
        # 1. Sanitise + validate (Pydantic already ran; this is belt and braces)
        sanitized_email = sanitize_email(user_data.email)
        password = user_data.password.get_secret_value()
        validate_password_strength(password)

        # 2. Uniqueness check
        if await database_service.get_user_by_email(sanitized_email):
            raise HTTPException(status_code=400, detail="Email already registered")

        # 3. Hash, then persist. The plaintext never leaves this function.
        hashed = User.hash_password(password)
        user = await database_service.create_user(email=sanitized_email,
                                                  password_hash=hashed)

        # 4. Auto-login: no second round trip to use the account
        token = create_access_token(str(user.id))
        return UserResponse(id=user.id, email=user.email, token=token)

    except ValueError as ve:
        logger.warning("registration_validation_failed", error=str(ve))
        raise HTTPException(status_code=422, detail=str(ve))
This endpoint is a user enumeration oracle

"Email already registered" tells an anonymous caller which addresses have accounts. That is a deliberate usability trade almost every product makes, but it is a trade — the privacy-preserving alternative is to always return 202 and send a "you already have an account" email instead. Rate limiting the endpoint (as done here) limits harvesting speed; it does not close the oracle.

@router.post("/login", response_model=TokenResponse)
@limiter.limit(settings.RATE_LIMIT_ENDPOINTS["login"][0])
async def login(
    request: Request,
    # OAuth2 password flow uses form fields, not JSON. This is what makes
    # the "Authorize" button work in /docs.
    username: str = Form(...),
    password: str = Form(...),
    grant_type: str = Form(default="password"),
):
    try:
        username = sanitize_string(username)
        password = sanitize_string(password)

        if grant_type != "password":
            raise HTTPException(status_code=400, detail="Unsupported grant type")

        user = await database_service.get_user_by_email(username)

        # One message for both cases: "no such user" and "wrong password"
        # are indistinguishable to the caller.
        if not user or not user.verify_password(password):
            logger.warning("login_failed", email=username)
            raise HTTPException(status_code=401,
                                detail="Incorrect email or password",
                                headers={"WWW-Authenticate": "Bearer"})

        token = create_access_token(str(user.id))
        logger.info("user_logged_in", user_id=user.id)
        return TokenResponse(access_token=token.access_token, token_type="bearer",
                             expires_at=token.expires_at)
    except ValueError as ve:
        raise HTTPException(status_code=422, detail=str(ve))
Sanitising the password is a subtle trap

sanitize_string HTML-escapes its input, so a password containing & or < becomes a different string. As long as registration applies the exact same transformation the hashes match and nobody notices — but the two paths are now coupled forever, and changing the sanitiser would lock out every affected user. Passwords are opaque bytes; hash them as given.

Sessions

@router.post("/session", response_model=SessionResponse)
async def create_session(user: User = Depends(get_current_user)):
    session_id = str(uuid.uuid4())          # unguessable, not sequential
    session = await database_service.create_session(session_id, user.id)

    # A token scoped to this thread only
    token = create_access_token(session_id)
    logger.info("session_created", session_id=session_id, user_id=user.id)
    return SessionResponse(session_id=session_id, name=session.name, token=token)


@router.get("/sessions", response_model=List[SessionResponse])
async def get_user_sessions(user: User = Depends(get_current_user)):
    sessions = await database_service.get_user_sessions(user.id)
    return [
        SessionResponse(session_id=s.id, name=s.name,
                        token=create_access_token(s.id))   # re-issued so the UI can resume
        for s in sessions
    ]

Real-time streaming with SSE

Server-Sent Events is a one-directional text protocol over plain HTTP: frames of data: <payload>\n\n, held open until the server closes it. No WebSocket handshake, no extra infrastructure, and every browser speaks it natively via EventSource. 

@router.post("/chat/stream")
@limiter.limit(settings.RATE_LIMIT_ENDPOINTS["chat_stream"][0])
async def chat_stream(request: Request, chat_request: ChatRequest,
                      session: Session = Depends(get_current_session)):
    try:
        logger.info("stream_chat_init", session_id=session.id)

        async def event_generator():
            try:
                async for chunk in agent.get_stream_response(
                    chat_request.messages,
                    session_id=session.id,
                    user_id=str(session.user_id),
                ):
                    # Structured frames, not bare text — the client can tell
                    # content from control without parsing prose.
                    response = StreamResponse(content=chunk, done=False)
                    yield f"data: {json.dumps(response.model_dump())}\n\n"

                # Explicit terminator so the client stops listening
                final_response = StreamResponse(content="", done=True)
                yield f"data: {json.dumps(final_response.model_dump())}\n\n"

            except Exception as e:
                # CRITICAL: headers were already sent, so you cannot switch
                # to a 500 here. The error must be delivered IN the stream.
                logger.error("stream_crash", session_id=session.id, error=str(e))
                error_response = StreamResponse(content=f"Error: {str(e)}", done=True)
                yield f"data: {json.dumps(error_response.model_dump())}\n\n"

        return StreamingResponse(event_generator(), media_type="text/event-stream")

    except Exception as e:
        # Only reachable before the first byte is written
        logger.error("stream_request_failed", session_id=session.id, error=str(e))
        raise HTTPException(status_code=500, detail=str(e))
Two try/except blocks, two different worlds

The outer one can still return a proper HTTP error, because nothing has been written yet. The inner one cannot — the status line and headers left the building the moment StreamingResponse started. Anything that fails mid-stream must be encoded as a frame, or the client sees a truncated response with a 200 status and no idea whether it is complete. This asymmetry is the single most common bug in hand-rolled streaming endpoints.

Aggregating the routers

api_router = APIRouter()

api_router.include_router(auth_router,    prefix="/auth",    tags=["auth"])
api_router.include_router(chatbot_router, prefix="/chatbot", tags=["chatbot"])


@api_router.get("/health")
async def health_check():
    """Liveness probe. Cheap on purpose — load balancers poll it constantly."""
    return {"status": "healthy", "version": "1.0.0"}

One aggregation point means src/main.py mounts a single router at settings.API_V1_STR, and /api/v2 later is a new module rather than a rewrite. The tags are what group the endpoints in /docs.
