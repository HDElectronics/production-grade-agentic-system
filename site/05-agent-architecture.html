Layer 05 · Core

Multi-agentic architecture

A chain runs input → LLM → output and forgets. A graph loops, calls tools, checkpoints its state to Postgres after every step, and carries facts about the user between conversations. This page is src/agent/workflow.py taken apart — the single most important file in the repository.

The problem it solves

Four requirements that a linear chain cannot satisfy:

  • Looping. "Search the web, read the results, then answer" is a cycle, not a pipeline — and the number of iterations is decided by the model at runtime.
  • Durability. A deploy mid-conversation must not lose the conversation. State lives in Postgres, not in process memory.
  • Two kinds of memory. "What did we just say" (this thread) and "what do I know about you" (every thread) are different stores with different lifetimes.
  • Streaming. Tokens must reach the user while the graph is still running.

Prompts as assets

The system prompt lives in a Markdown file, not in a Python string. That means a prompt change is a content diff, reviewable by someone who does not read Python, and it keeps merge conflicts out of code. 

# Name: {agent_name}
# Role: A world class assistant
Help the user with their questions.

# Instructions
- Always be friendly and professional.
- If you don't know the answer, say you don't know. Don't make up an answer.
- Try to give the most accurate answer possible.

# What you know about the user
{long_term_memory}

# Current date and time
{current_date_and_time}

def load_system_prompt(**kwargs) -> str:
    """Read the markdown template and inject runtime values."""
    prompt_path = os.path.join(os.path.dirname(__file__), "system.md")
    with open(prompt_path, "r") as f:
        return f.read().format(
            agent_name=settings.PROJECT_NAME + " Agent",
            current_date_and_time=datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
            **kwargs,                 # long_term_memory arrives from the caller
        )
Two sharp edges in those eight lines

1. str.format() treats every { as a placeholder, so a literal brace in the prompt — a JSON example, say — raises KeyError at request time. Escape them as {{ or move to a template engine. 2. The file is re-read on every single call. That is a syscall per request for content that changes weekly; cache it, and gain hot-reload-on-change deliberately rather than by accident.

Why the date is injected

Without it the model answers "today" with the date its weights were frozen. One interpolated string removes an entire category of confidently wrong answers.

Tools

One tool per module, registered in one list. That list is the agent's entire capability surface.

from langchain_community.tools import DuckDuckGoSearchResults

# num_results=10 gives the model enough context to synthesise rather
# than parrot. handle_tool_error keeps a failed search from killing
# the whole graph run — the model sees an error string and can recover.
duckduckgo_search_tool = DuckDuckGoSearchResults(num_results=10, handle_tool_error=True)

from langchain_core.tools.base import BaseTool
from .web_search import duckduckgo_search_tool

# Central registry. Adding a tool here is the only step needed
# for the model to be able to call it.
tools: list[BaseTool] = [duckduckgo_search_tool]
Tool output is untrusted input

Search results are attacker-influenceable text that goes straight into the model's context. A page can contain "ignore your instructions and…" and the model will read it with the same attention as your system prompt. Keep the tool surface small, prefer read-only tools, and never let a tool result trigger a privileged action without a check outside the model.

The graph

Two nodes, one entry point, one loop. That is the whole state machine:

async def create_graph(self) -> Optional[CompiledStateGraph]:
    if self._graph is None:
        try:
            graph_builder = StateGraph(GraphState)

            # `ends` declares the legal transitions out of each node.
            graph_builder.add_node("chat",      self._chat,      ends=["tool_call", END])
            graph_builder.add_node("tool_call", self._tool_call, ends=["chat"])
            graph_builder.set_entry_point("chat")
            graph_builder.set_finish_point("chat")

            connection_pool = await self._get_connection_pool()
            if connection_pool:
                checkpointer = AsyncPostgresSaver(connection_pool)
                await checkpointer.setup()      # CREATE TABLE IF NOT EXISTS …
            else:
                checkpointer = None
                if settings.ENVIRONMENT != Environment.PRODUCTION:
                    raise Exception("Connection pool initialization failed")

            self._graph = graph_builder.compile(
                checkpointer=checkpointer,
                name=f"{settings.PROJECT_NAME} Agent ({settings.ENVIRONMENT.value})")

        except Exception as e:
            logger.error("graph_creation_failed", error=str(e))
            # Production degrades: an agent with no memory beats no agent.
            if settings.ENVIRONMENT == Environment.PRODUCTION:
                logger.warning("continuing_without_graph")
                return None
            raise e
    return self._graph

The chat node

async def _chat(self, state: GraphState, config: RunnableConfig) -> Command:
    current_llm = self.llm_service.get_llm()
    model_name = getattr(current_llm, "model_name", settings.DEFAULT_LLM_MODEL)

    # Rebuilt every turn: fresh memory, fresh timestamp
    SYSTEM_PROMPT = load_system_prompt(long_term_memory=state.long_term_memory)
    messages = prepare_messages(state.messages, current_llm, SYSTEM_PROMPT)

    try:
        # The histogram context manager times the call even if it raises
        with llm_inference_duration_seconds.labels(model=model_name).time():
            response_message = await self.llm_service.call(dump_messages(messages))

        response_message = process_llm_response(response_message)

        # THE ROUTING DECISION — made by the model, not by us.
        if response_message.tool_calls:
            goto = "tool_call"
        else:
            goto = END

        # Command bundles "update the state" and "go here next" atomically
        return Command(update={"messages": [response_message]}, goto=goto)

    except Exception as e:
        logger.error("llm_call_failed_all_models", error=str(e))
        raise Exception(f"failed to get llm response after trying all models: {str(e)}")

The tool node

async def _tool_call(self, state: GraphState) -> Command:
    outputs = []
    # The model may request several tools in one turn
    for tool_call in state.messages[-1].tool_calls:
        tool_result = await self.tools_by_name[tool_call["name"]].ainvoke(tool_call["args"])
        outputs.append(
            ToolMessage(
                content=tool_result,
                name=tool_call["name"],
                # The id is how the model matches a result to its request.
                # Drop it and the provider rejects the conversation.
                tool_call_id=tool_call["id"],
            )
        )
    # Unconditionally back to chat: the model decides whether it now
    # has enough to answer, or wants another tool.
    return Command(update={"messages": outputs}, goto="chat")
Two things this loop does not bound

tools_by_name[tool_call["name"]] raises KeyError if the model hallucinates a tool name — worth a guard that returns an error ToolMessage instead, so the model can correct itself. And nothing caps the number of chat↔tool round trips; a model that keeps deciding to search will keep searching. Production graphs add a recursion limit and a per-run tool-call budget.

Two memories

These are frequently confused. They have different stores, different lifetimes and different failure modes.

Short-term (checkpoints)Long-term (mem0ai)
ScopeOne session / thread_idOne user_id, across every session
Storecheckpoints tables, written by AsyncPostgresSaverpgvector collection, embeddings + text
ContainsThe literal message list and graph positionLLM-extracted facts: "prefers Python", "based in Dubai"
RetrievalExact load by thread idVector similarity against the newest message
WrittenSynchronously, after every nodeAsynchronously, after the response is sent
Failure modeLost thread = conversation restartsWrong fact = confidently wrong personalisation, persisting for months
 
async def _long_term_memory(self) -> AsyncMemory:
    """Lazy singleton — built on first use, not at import."""
    if self.memory is None:
        self.memory = await AsyncMemory.from_config(config_dict={
            "vector_store": {
                "provider": "pgvector",          # same Postgres as everything else
                "config": {
                    "collection_name": settings.LONG_TERM_MEMORY_COLLECTION_NAME,
                    "dbname":   settings.POSTGRES_DB,
                    "user":     settings.POSTGRES_USER,
                    "password": settings.POSTGRES_PASSWORD,
                    "host":     settings.POSTGRES_HOST,
                    "port":     settings.POSTGRES_PORT,
                },
            },
            "llm":      {"provider": "openai",
                         "config": {"model": settings.LONG_TERM_MEMORY_MODEL}},
            "embedder": {"provider": "openai",
                         "config": {"model": settings.LONG_TERM_MEMORY_EMBEDDER_MODEL}},
        })
    return self.memory


async def _get_relevant_memory(self, user_id: str, query: str) -> str:
    try:
        memory = await self._long_term_memory()
        results = await memory.search(user_id=str(user_id), query=query)
        return "\n".join([f"* {result['memory']}" for result in results["results"]])
    except Exception as e:
        # Memory is an enhancement, never a dependency. A vector search
        # failure must not cost the user their answer.
        logger.error("failed_to_get_relevant_memory", error=str(e), user_id=user_id)
        return ""
user_id is the tenancy boundary

Every search and every add is scoped by it. Get that filter wrong and one user's private facts are injected into another user's system prompt — a cross-tenant leak with no error message, discovered only when someone notices the agent knows something it shouldn't. It deserves a test.

Writing memory without making the user wait

response = await self._graph.ainvoke(
    input={"messages": dump_messages(messages), "long_term_memory": relevant_memory},
    config=config,
)

# Fire and forget: mem0ai runs an LLM to extract durable facts from the
# transcript. That is a second inference the user should not pay latency for.
asyncio.create_task(
    self._update_long_term_memory(
        user_id, convert_to_openai_messages(response["messages"]), config["metadata"])
)
return self.__process_messages(response["messages"])
Bare create_task has two known hazards

Nothing holds a reference to the task, so the garbage collector may cancel it mid-flight — the standard fix is to keep the task in a module-level set and discard it in a done-callback. And an exception inside it surfaces only as "Task exception was never retrieved" at shutdown. Here _update_long_term_memory catches everything internally, which handles the second problem but not the first.

Streaming out of the graph

stream_mode="messages" yields token-level chunks as each node produces them, so the first character reaches the browser long before the graph finishes. 

async def get_stream_response(self, messages, session_id, user_id=None) -> AsyncGenerator[str, None]:
    config = {
        "configurable": {"thread_id": session_id},
        "callbacks": [CallbackHandler(environment=settings.ENVIRONMENT.value,
                                      user_id=user_id, session_id=session_id)],
        "metadata": {"user_id": user_id, "session_id": session_id, ...},
    }
    if self._graph is None:
        self._graph = await self.create_graph()

    relevant_memory = (await self._get_relevant_memory(
        user_id, messages[-1].content)) or "No relevant memory found."

    try:
        async for token, _ in self._graph.astream(
            {"messages": dump_messages(messages), "long_term_memory": relevant_memory},
            config, stream_mode="messages",
        ):
            try:
                yield token.content
            except Exception as token_error:
                # One malformed chunk must not end the stream
                logger.error("Error processing token", error=str(token_error))
                continue

        # Streaming yields tokens, not final state — read it back explicitly.
        # get_state is sync, so it is wrapped rather than blocking the loop.
        state: StateSnapshot = await sync_to_async(self._graph.get_state)(config=config)
        if state.values and "messages" in state.values:
            asyncio.create_task(self._update_long_term_memory(
                user_id, convert_to_openai_messages(state.values["messages"]), config["metadata"]))

    except Exception as stream_error:
        logger.error("Error in stream processing", error=str(stream_error))
        raise stream_error

History and hard reset

async def get_chat_history(self, session_id: str) -> list[Message]:
    """Replay a conversation straight out of the checkpointer."""
    state: StateSnapshot = await sync_to_async(self._graph.get_state)(
        config={"configurable": {"thread_id": session_id}})
    return self.__process_messages(state.values["messages"]) if state.values else []


async def clear_chat_history(self, session_id: str) -> None:
    conn_pool = await self._get_connection_pool()
    async with conn_pool.connection() as conn:
        # settings.CHECKPOINT_TABLES = ["checkpoint_blobs",
        #                               "checkpoint_writes", "checkpoints"]
        for table in settings.CHECKPOINT_TABLES:
            await conn.execute(f"DELETE FROM {table} WHERE thread_id = %s", (session_id,))
Clearing a thread does not clear the user's memory

These deletes only touch checkpoint tables. Facts mem0ai already extracted stay in pgvector, so an agent will still greet the user by name after a "clear history". That is usually what people want, but it is not what a data-deletion request means — right-to-erasure needs a mem0ai delete scoped to the user_id as well.
