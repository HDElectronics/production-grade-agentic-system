Layer 02 · Foundations

Data persistence

Two type systems, deliberately kept apart: models describe what lives in Postgres, schemas describe what crosses the network. Collapsing them is how password hashes end up in JSON responses.

The problem it solves

An agentic system is not a JSON blob store. There are hard relationships — a user owns sessions, a session anchors a LangGraph thread, a thread owns checkpoints — and violating them corrupts conversations rather than just losing a row. At the same time, the shape you persist is not the shape you should return: the User row carries hashed_password, and the API must never emit it.

The stack here is SQLModel, which is SQLAlchemy (persistence) and Pydantic (validation) in one class hierarchy — so the two worlds can share syntax without sharing objects.

The base model (DRY)

Every table needs a creation timestamp. Copy-pasting that field into every model is how one table ends up with a naive local timestamp while the rest are UTC, and how a 2 a.m. incident becomes unreadable. 

from datetime import datetime, UTC
from sqlmodel import Field, SQLModel


class BaseModel(SQLModel):
    """Abstract base adding common fields to all tables."""

    # Always UTC in production. Timezone-naive timestamps are a
    # debugging tax you pay forever.
    created_at: datetime = Field(default_factory=lambda: datetime.now(UTC))
Note the default_factory

default=datetime.now(UTC) would evaluate once, at import time, and stamp every row ever created with the moment your process booted. The lambda defers evaluation to insert time. This is one of the most common Python bugs that never throws an exception.

Entity definition

User — with the crypto encapsulated

from typing import TYPE_CHECKING, List
import bcrypt
from sqlmodel import Field, Relationship
from src.data.models.base import BaseModel

if TYPE_CHECKING:                       # type-only import: no circular import at runtime
    from src.data.models.session import Session


class User(BaseModel, table=True):
    id: int = Field(default=None, primary_key=True)

    # unique -> a DB-level guarantee, not just an application check
    # index  -> login does WHERE email = ? on every request
    email: str = Field(unique=True, index=True)

    hashed_password: str                # never the plaintext

    sessions: List["Session"] = Relationship(back_populates="user")

    def verify_password(self, password: str) -> bool:
        return bcrypt.checkpw(password.encode("utf-8"),
                              self.hashed_password.encode("utf-8"))

    @staticmethod
    def hash_password(password: str) -> str:
        salt = bcrypt.gensalt()         # a fresh salt per password
        return bcrypt.hashpw(password.encode("utf-8"), salt).decode("utf-8")

Putting verify_password and hash_password on the model is the point. No route handler ever gets a chance to invent its own comparison, and nobody writes if user.hashed_password == password. The unsafe operation is simply not reachable.

bcrypt.checkpw is constant-time by design

It compares the full digest rather than short-circuiting on the first differing byte, so an attacker can't measure response times to learn the hash prefix. A hand-rolled == on hashes leaks exactly that.

Session — the conversation boundary

class Session(BaseModel, table=True):
    # String UUIDs, not autoincrement ints. Session ids travel in tokens
    # and URLs; sequential ids let anyone enumerate their neighbours' chats.
    id: str = Field(primary_key=True)

    user_id: int = Field(foreign_key="user.id")
    name: str = Field(default="")               # friendly label, e.g. "Recipe ideas"

    user: "User" = Relationship(back_populates="sessions")

Thread — the anchor for LangGraph state

class Thread(SQLModel, table=True):
    """Lightweight anchor for LangGraph checkpoints.

    The state blob itself is written by AsyncPostgresSaver into
    checkpoints / checkpoint_blobs / checkpoint_writes. This table
    exists so the application can validate that a thread exists
    without reaching into the checkpointer's private tables.
    """
    id: str = Field(primary_key=True)
    created_at: datetime = Field(default_factory=lambda: datetime.now(UTC))

The resulting schema — note the cascade and the two indexes:

CREATE TABLE IF NOT EXISTS user (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    email           TEXT UNIQUE NOT NULL,
    hashed_password TEXT NOT NULL,
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS session (
    id         TEXT PRIMARY KEY,
    user_id    INTEGER NOT NULL,
    name       TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS thread (
    id         TEXT PRIMARY KEY,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_user_email      ON user(email);
CREATE INDEX IF NOT EXISTS idx_session_user_id ON session(user_id);
Where the rest of the tables come from

checkpoints, checkpoint_blobs and checkpoint_writes are created by await checkpointer.setup() at agent startup, not by this file. They are listed in settings.CHECKPOINT_TABLES so clear_chat_history() knows what to delete — see layer 05. The pgvector collection is created by mem0ai.

Data Transfer Objects

A DTO is the contract between your API and the outside world. Returning ORM objects directly couples your wire format to your table layout — rename a column and you break every client — and leaks whatever fields happen to exist. 

import re
from datetime import datetime
from pydantic import BaseModel, EmailStr, Field, SecretStr, field_validator


class UserCreate(BaseModel):
    """Registration input."""
    email: EmailStr = Field(..., description="User's email address")

    # SecretStr renders as '**********' in reprs and tracebacks, so an
    # unhandled exception can't print the password into your logs.
    password: SecretStr = Field(..., min_length=8, max_length=64)

    @field_validator("password")
    @classmethod
    def validate_password(cls, v: SecretStr) -> SecretStr:
        password = v.get_secret_value()
        if len(password) < 8:
            raise ValueError("Password must be at least 8 characters long")
        if not re.search(r"[A-Z]", password):
            raise ValueError("Password must contain at least one uppercase letter")
        if not re.search(r"[0-9]", password):
            raise ValueError("Password must contain at least one number")
        if not re.search(r'[!@#$%^&*(),.?":{}|<>]', password):
            raise ValueError("Password must contain at least one special character")
        return v


class Token(BaseModel):
    access_token: str
    token_type: str = Field(default="bearer")
    expires_at: datetime


class UserResponse(BaseModel):
    """Public profile. Note what is NOT here: hashed_password."""
    id: int
    email: str
    token: Token

Chat schemas

The chat DTOs do double duty: they define the wire format and they are the first line of input defence, because a Pydantic validator runs before your handler body does. 

class Message(BaseModel):
    role: Literal["user", "assistant", "system"] = Field(...)
    content: str = Field(..., min_length=1, max_length=3000)

    @field_validator("content")
    @classmethod
    def validate_content(cls, v: str) -> str:
        if re.search(r"<script.*?>.*?</script>", v, re.IGNORECASE | re.DOTALL):
            raise ValueError("Content contains potentially harmful script tags")
        return v


class ChatRequest(BaseModel):
    messages: List[Message] = Field(..., min_length=1)


class ChatResponse(BaseModel):
    messages: List[Message]


class StreamResponse(BaseModel):
    """One Server-Sent Events frame."""
    content: str = Field(default="")
    done: bool = Field(default=False)

Three constraints are doing real work here:

  • Literal[...] on role — a client cannot invent a "developer" role and confuse the model's chat template.
  • max_length=3000 — a bound on the per-message token cost before the request reaches the LLM. Combined with the trimming in layer 03, cost per request is capped from both ends.
  • min_length=1 on messages — the agent indexes messages[-1] to build the memory query; an empty list would be an IndexError deep inside the graph.
The script-tag validator is defence in depth, not the defence

A regex for <script>…</script> catches the naive case and nothing else — it does not stop <img onerror=…>. The actual protection is the escaping in sanitize_string() (layer 03) plus not rendering model output as raw HTML. Treat this validator as a cheap tripwire.

The graph state schema

LangGraph passes one state object between nodes. Declaring it as a Pydantic model — rather than a loose dict — means a typo in a node's return value fails immediately instead of silently creating a new key. 

from typing import Annotated
from langgraph.graph.message import add_messages
from pydantic import BaseModel, Field


class GraphState(BaseModel):
    # add_messages is a REDUCER. Without it, a node returning
    # {"messages": [x]} would REPLACE the history with [x].
    # With it, LangGraph appends and de-duplicates by message id.
    messages: Annotated[list, add_messages] = Field(default_factory=list)

    # Retrieved from mem0ai before the graph runs; injected into the
    # system prompt by the chat node.
    long_term_memory: str = Field(default="")
