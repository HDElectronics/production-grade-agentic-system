Layer 01 · Foundations

Modular codebase

Dependencies, environment-aware settings and container topology. This is the least glamorous layer and the one that decides whether the next nine are survivable — every later page imports settings and assumes a service is reachable by name.

The problem it solves

Python projects start as one file and rot into a ball of mud. In an agentic system the rot is expensive in a specific way: config values (model name, temperature, pool size, rate limits) end up hard-coded in a dozen places, so "turn the temperature down in production" becomes a code change, a review, and a deploy instead of an environment variable.

Three rules carry this layer:

  • One module, one concern. API routing does not know how the LLM is called; the LLM service does not know a request exists.
  • Config is data, not code. Everything that differs between laptop and production is read from the environment.
  • The environment is reproducible. If the database only exists on your machine, you don't have a system, you have a demo.

The shipped code in this repository uses the same architecture with more descriptive names:

src/
├── main.py                   # FastAPI app: lifespan, middleware, exception handlers
├── config/settings.py        # Environment-aware settings object
├── interface/                # HTTP layer  (auth.py, interaction.py, router.py)
├── agent/                    # LangGraph agent (workflow.py, tools/, prompts/)
├── services/llm_provider.py  # Retry + circular fallback around the LLM
├── data/                     # db_manager.py, models/, schemas/
├── system/                   # logs.py, telemetry.py, middleware.py, rate_limit.py
└── utils/                    # auth.py, sanitization.py, graph.py
Why the split matters later

src/system/ holds everything that wraps every request (logging, metrics, limits). src/services/ holds things a route calls on purpose. Keeping those apart is what lets layer 07 add observability without touching a single route handler.

Dependency management

requirements.txt gives you a flat list with no metadata, no dependency groups and no tool configuration. pyproject.toml (PEP 621) gives you all three in one file, which matters when the formatter, the linter, the test runner and the packaging metadata all need to agree. 

[project]
name = "My Agentic AI System"

description = "Deploying it as a SaaS"

Read the version operators carefully

Almost everything uses >=, but langfuse==3.9.1 is pinned exactly. That asymmetry is deliberate: floors keep you patchable, exact pins are for libraries whose minor releases break you. The lockfile (uv.lock) is what actually makes builds reproducible — the ranges here only describe what is acceptable.

Development and test dependencies stay out of the production image:

Environment configuration

A single .env forces you to edit the file every time you switch context. The pattern here is one file per environment — .env.development, .env.staging, .env.production — with .env.example committed as the documented template, and the real files gitignored.

PROJECT_NAME="Project Name"
DEBUG=true
API_V1_STR=/api/v1

Resolving which file wins

src/config/settings.py decides the environment first, then walks a priority list and loads the first file that exists. Local overrides beat committed defaults, and nothing needs a command-line flag. 

class Environment(str, Enum):
    DEVELOPMENT = "development"
    STAGING     = "staging"
    PRODUCTION  = "production"
    TEST        = "test"


def get_environment() -> Environment:
    match os.getenv("APP_ENV", "development").lower():
        case "production" | "prod": return Environment.PRODUCTION
        case "staging"    | "stage": return Environment.STAGING
        case "test":                 return Environment.TEST
        case _:                      return Environment.DEVELOPMENT


def load_env_file():
    """Load the highest-priority .env file that exists."""
    env = get_environment()
    base_dir = os.path.dirname(os.path.dirname(os.path.dirname(__file__)))

    env_files = [
        os.path.join(base_dir, f".env.{env.value}.local"),  # personal, gitignored
        os.path.join(base_dir, f".env.{env.value}"),        # per-environment
        os.path.join(base_dir, ".env.local"),               # local catch-all
        os.path.join(base_dir, ".env"),                     # last resort
    ]
    for env_file in env_files:
        if os.path.isfile(env_file):
            load_dotenv(dotenv_path=env_file)
            return env_file
    return None


ENV_FILE = load_env_file()          # runs at import time

Parsing structured values out of flat strings

Environment variables are strings. Lists and per-endpoint maps need helpers, and those helpers need to be forgiving about quoting because .env files are edited by humans and by shell scripts. 

def parse_list_from_env(env_key, default=None):
    """ALLOWED_ORIGINS="a,b" -> ["a", "b"]"""
    value = os.getenv(env_key)
    if not value:
        return default or []
    value = value.strip("\"'")               # tolerate quoted values
    if "," not in value:
        return [value]
    return [item.strip() for item in value.split(",") if item.strip()]


def parse_dict_of_lists_from_env(prefix, default_dict=None):
    """RATE_LIMIT_CHAT="100 per minute" -> {"chat": ["100 per minute"]}"""
    result = default_dict or {}
    for key, value in os.environ.items():
        if key.startswith(prefix):
            endpoint = key[len(prefix):].lower()
            if value:
                value = value.strip("\"'")
                result[endpoint] = ([item.strip() for item in value.split(",") if item.strip()]
                                    if "," in value else [value])
    return result

The safety net: environment overrides

This is the most important twenty lines in the file. Whatever the .env says, production forces debug off, logs to JSON, and tightens the default rate limits. A misconfigured deploy degrades into a safe configuration rather than a leaky one. 

class Settings:
    def __init__(self):
        self.ENVIRONMENT = get_environment()

        self.PROJECT_NAME = os.getenv("PROJECT_NAME", "FastAPI LangGraph Agent")
        self.API_V1_STR   = os.getenv("API_V1_STR", "/api/v1")
        self.DEBUG        = os.getenv("DEBUG", "false").lower() in ("true", "1", "t", "yes")
        self.ALLOWED_ORIGINS = parse_list_from_env("ALLOWED_ORIGINS", ["*"])

        self.DEFAULT_LLM_MODEL       = os.getenv("DEFAULT_LLM_MODEL", "gpt-4o-mini")
        self.DEFAULT_LLM_TEMPERATURE = float(os.getenv("DEFAULT_LLM_TEMPERATURE", "0.2"))
        self.MAX_TOKENS              = int(os.getenv("MAX_TOKENS", "2000"))
        self.MAX_LLM_CALL_RETRIES    = int(os.getenv("MAX_LLM_CALL_RETRIES", "3"))

        self.POSTGRES_POOL_SIZE    = int(os.getenv("POSTGRES_POOL_SIZE", "20"))
        self.POSTGRES_MAX_OVERFLOW = int(os.getenv("POSTGRES_MAX_OVERFLOW", "10"))
        # Tables LangGraph's Postgres checkpointer owns
        self.CHECKPOINT_TABLES = ["checkpoint_blobs", "checkpoint_writes", "checkpoints"]

        self.JWT_SECRET_KEY = os.getenv("JWT_SECRET_KEY", "unsafe-secret-for-dev")
        self.RATE_LIMIT_DEFAULT = parse_list_from_env(
            "RATE_LIMIT_DEFAULT", ["200 per day", "50 per hour"])
        self.RATE_LIMIT_ENDPOINTS = {
            "chat":        parse_list_from_env("RATE_LIMIT_CHAT",        ["30 per minute"]),
            "chat_stream": parse_list_from_env("RATE_LIMIT_CHAT_STREAM", ["20 per minute"]),
            "auth":        parse_list_from_env("RATE_LIMIT_LOGIN",       ["20 per minute"]),
            "root":        parse_list_from_env("RATE_LIMIT_ROOT",        ["10 per minute"]),
            "health":      parse_list_from_env("RATE_LIMIT_HEALTH",      ["20 per minute"]),
        }

        self.apply_environment_settings()

    def apply_environment_settings(self):
        """Rigorous overrides. Production stays safe even if .env is wrong."""
        if self.ENVIRONMENT == Environment.DEVELOPMENT:
            self.DEBUG      = True
            self.LOG_LEVEL  = "DEBUG"
            self.LOG_FORMAT = "console"
            self.RATE_LIMIT_DEFAULT = ["1000 per day", "200 per hour"]

        elif self.ENVIRONMENT == Environment.PRODUCTION:
            self.DEBUG      = False          # never leak tracebacks
            self.LOG_LEVEL  = "WARNING"
            self.LOG_FORMAT = "json"         # machine-parseable
            self.RATE_LIMIT_DEFAULT = ["200 per day", "50 per hour"]


settings = Settings()                        # single global instance

Containerisation strategy

The agent needs a vector store, metrics collection, dashboards and container-level resource stats. Running those by hand is not reproducible, so the whole topology is declared in docker-compose.yml. 

services:
  db:
    image: pgvector/pgvector:pg16      # NOT plain postgres: we need vectors
    environment:
      - POSTGRES_DB=${POSTGRES_DB}
      - POSTGRES_USER=${POSTGRES_USER}
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    ports: ["5432:5432"]
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:                       # the app waits on this
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: always
    networks: [monitoring]
Why pgvector, not postgres

One database serves three jobs here: relational rows (users, sessions), LangGraph checkpoint blobs, and mem0ai's embedding index. The third needs the vector extension. Using the pgvector image means one container instead of a separate vector database — a real reduction in operational surface at this scale.

  app:
    build:
      context: .
      args:
        APP_ENV: ${APP_ENV:-development}
    ports: ["8000:8000"]
    volumes:
      - ./app:/app/app              # bind mount => hot reload in dev
      - ./logs:/app/logs
    env_file:
      - .env.${APP_ENV:-development}
    depends_on:
      db:
        condition: service_healthy  # not just "started" — actually accepting connections
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      start_period: 10s
    restart: on-failure
    networks: [monitoring]

condition: service_healthy is the line that stops the classic startup race, where the API boots, tries SQLModel.metadata.create_all() against a Postgres that is still initialising, and dies.
